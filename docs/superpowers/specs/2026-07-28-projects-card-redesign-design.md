# إعادة تصميم بطاقة المشروع وشريط الفلاتر — بأسلوب Mada Properties

> التاريخ: ٢٨ يوليو ٢٠٢٦
> المرجع البصري: <https://madaproperties.sa/ar/projects>
> النطاق: `projects.html` + الشبكة المميّزة في `index.html` (نفس المكوّن)

---

## ١. المشكلة

بطاقة المشروع الحالية «صورة فوق + صندوق نص تحت»: الصورة تاخذ ثلث البطاقة، والنص في لوح
منفصل. النتيجة أن العقار — وهو المنتج — يجي في المرتبة الثانية بصريًا، وكل بطاقة تستهلك
ارتفاعًا كبيرًا مقابل معلومة قليلة.

موقع Mada يحلّها ببطاقة **كاملة الصورة**: الصورة هي البطاقة، والبيانات تجلس فوقها على
تدرّج داكن. الصورة تكبر ×٣ تقريبًا بنفس الارتفاع، والمعلومات المهمّة (الحالة، النوع،
الغرف، السعر) تظهر كلها بلا تمرير.

المطلوب: **بنية Mada وتخطيطها، بهوية رايليست البصرية** — لا نسخ ألوانهم (`#8EC24D`
أخضر) ولا خطوطهم (Tajawal).

## ٢. الحالة الراهنة (متحقَّق منها من قاعدة البيانات، لا من `data.js`)

> `assets/js/data.js` المُلتزَم في git هو ملف بذور قديم (٩ مشاريع وهمية بصور Unsplash)،
> يُعاد توليده بالكامل وقت البناء عبر `writeDataJs`. **لمعرفة المحتوى الحي: استعلم من
> Supabase** (ref `ghtcwsbtyvczlznviojj`).

٦ مشاريع حيّة، كلها بصور حقيقية ومعارض كاملة:

| الكود | صورة الغلاف | المعرض | المدينة | النوع | الحالة |
|---|---|---|---|---|---|
| `ALALYAA` | `alalyaa-hero.jpg` | ٣٠ | المدينة المنورة | شقق | متاح |
| `NAJD-2` | `najd2-hero.jpg` | ١٧ | الرياض | شقق | متاح |
| `NAJD-3` | `najd3-hero.jpg` | ١٨ | الرياض | شقق | متاح |
| `NAJD-4` | `najd4-hero.jpg` | ٢٣ | الرياض | تاون هاوس | متاح |
| `NAJD-5` | `najd5-hero.jpg` | ١٢ | الرياض | تاون هاوس | متاح |
| `NAJD-7` | `najd7-hero.jpg` | ٣١ | الرياض | شقق | متاح |

**لا توجد صور بديلة (placeholders) على الموقع.** حملة الاستبدال في ١٤ يوليو انتهت
وعُبِّئت كل الخانات بصور حقيقية.

نتيجتان تصميميّتان:

1. النص الأبيض فوق التدرّج آمن — كل الصور معمارية حقيقية، ما فيه حالة شعار على خلفية
   عاجية فاتحة.
2. الفلاتر الحالية شبه ميّتة: **الحالة** قيمة واحدة فقط (`available` ×٦)،
   و**الأنواع** قيمتان، و**المدن** اثنتان من خمس فيها محتوى.

### ٤.١ التدرّج — التوكن الحرج

طبقة الثيم (سطر ٩٧٠+ في `styles.css`) تعيد تعريف `--ink: var(--fg)`. في الوضع الداكن
`--fg` يساوي `#ece6d8` — أي **فاتح تقريبًا**. فبناء التدرّج على `var(--ink)` ينتج تدرّجًا
فاتحًا في الوضع الداكن ويُخفي النص الأبيض.

**الحل:** توكن مستقل لا يُعاد تعريفه في أي ثيم:

```css
:root { --card-scrim: 23 20 15; }   /* قيم RGB مجرّدة */

.pcard__scrim {
  background: linear-gradient(
    to top,
    rgb(var(--card-scrim) / .92) 0%,
    rgb(var(--card-scrim) / .78) 28%,
    rgb(var(--card-scrim) / 0)   62%
  );
}
```

البطاقة تبقى «صورة داكنة» في الوضعين — سلوك مقصود ومتّسق.

### ٤.٢ الشرائح

تُبنى من دالة `chipsFor(p)`، وكل شريحة تُحذف إذا كان حقلها فارغًا (لا «—»، اتّساقًا مع
قاعدة الامتثال القائمة):

| الشريحة | المصدر | تظهر متى |
|---|---|---|
| الحالة | `p.status` | دائمًا |
| النوع | `p.typeAr/En/Zh` | إذا موجود |
| الغرف | `p.bedsMin`–`p.bedsMax` | إذا `bedsMax > 0` |
| المساحة | `p.area` | إذا موجود |
| الكود | `p.code` | إذا موجود (بمحاذاة معاكسة، مونو باهت) |

مظهرها زجاجي لا مصمت — تجلس فوق أي صورة:

```css
.pcard__chip {
  background: rgb(var(--card-scrim) / .55);
  backdrop-filter: blur(6px);
  color: #F6F3EB;
  border-radius: 999px;
}
.pcard__chip--available { color: var(--pale); }
.pcard__chip--reserved  { color: #E0B278; }
.pcard__chip--sold      { color: rgb(246 243 235 / .6); }
```

`backdrop-filter` غير مدعوم في متصفحات قديمة — الاحتياط هو الخلفية شبه‑الشفافة نفسها،
وهي كافية للتباين بلا الطمس.

### ٤.٣ السعر — مقايضة معلومة مقصودة

كل المشاريع الستة أسعارها **مدى** لا رقم واحد (مثال `NAJD-7`: ٢٬٥٠٠٬٠٠٠ – ٣٬٠٠٠٬٠٠٠).
البطاقة الحالية تعرض المدى كاملًا؛ البطاقة الجديدة تعرض **الحدّ الأدنى فقط** بصيغة
«يبدأ من ٢٬٥٠٠٬٠٠٠ ﷼» — تماشيًا مع «السعر المبدئي» عند Mada.

هذا **إسقاط متعمَّد للحدّ الأعلى من البطاقة**: سطر السعر داخل التراكب ضيّق، والمدى الكامل
بالعربية يلتفّ سطرين على الجوّال ويكسر التخطيط. المدى الكامل يبقى معروضًا في صفحة تفاصيل
المشروع، وتحفّظ «الأسعار قابلة للتغيير دون إشعار» قائم في الفوتر. لو أُريد المدى كاملًا
على البطاقة، البديل هو تصغير الخط إلى `0.95rem` وقبول الالتفاف على العروض الضيّقة.

`fmtPrice()` الحالية تبقى كما هي (تستعملها صفحات أخرى)؛ تُضاف `fmtPriceFrom(min)` مستقلّة.

### ٤.٤ نسبة المبيع

`sold` تساوي `0` لكل المشاريع الستة (متحقَّق منه)، فالشريط لا يظهر اليوم. يبقى المكوّن
مبنيًّا ليشتغل تلقائيًا: خيط ذهبي بارتفاع `3px` ملتصق بأسفل الصورة، مع نسبة مئوية صغيرة.

### ٤.٥ التفاعل والوصولية

- البطاقة كلها رابط عبر `::after` ممدود على `.project-card`؛ الحاوية `position: relative`.
- `.pcard__go` سهم دائري — إشارة بصرية فقط، `aria-hidden="true"`.
- عند المرور: `transform: scale(1.04)` على الصورة + توسيع فجوة السهم.
- النص البديل للصورة = اسم المشروع (قائم فعلًا).
- التركيز بلوحة المفاتيح يستخدم `:focus-visible` العام (`outline: 2px solid var(--champ)`)،
  لكنه يحتاج `outline-offset` سالبًا على البطاقة كي لا يُقصّ بـ `overflow: hidden`.
- الاتجاه: `inset-inline-start/end` حصرًا، لا `left/right`.

## ٥. تصميم شريط الفلاتر

```
٦ مشاريع

( الكل ) ( الرياض ) ( جدة ) ( المدينة المنورة ) ( الشرقية ) ( مكة )
   شقق · تاون هاوس
                                    ← صف الحالة مخفي (قيمة واحدة فقط)
```

### ٥.١ أي حبّة تظهر

| الصف | المصدر | القاعدة |
|---|---|---|
| المدن | ثابتة في HTML | كلها تظهر دائمًا |
| الأنواع | مشتقّة من `PROJECTS` | يظهر الصف إذا ≥ قيمتان مختلفتان |
| الحالة | مشتقّة من `PROJECTS` | يظهر الصف إذا ≥ قيمتان مختلفتان |

**المدن تُستثنى من الاشتقاق عمدًا:** ضغط «جدة» يطلّع رسالة «مشاريعنا في هذه المدينة
قريبًا · تواصل معنا» ([`main.js:150-156`](../../../assets/js/main.js)) — وهذي أداة التقاط
عملاء مقصودة، لا نتيجة فاشلة. أما الأنواع والحالة فاشتقاقها يعني أن الصفوف تكبر تلقائيًا
عند إضافة فلل أو مشروع مباع، بلا تعديل كود.

### ٥.٢ الحالة ومزامنة الرابط

- كل حبّة `<button role="tab">` مع `aria-selected`، داخل `<div role="tablist">` له
  `aria-label` وصفي.
- الحالة تُقرأ من الرابط عند التحميل (السلوك القائم في `initFiltersFromUrl`) وتُكتب فيه
  عند كل تغيير بـ `history.replaceState` — فيصير الفلتر قابل للمشاركة، وهي زيادة على
  الوضع الحالي.
- `replaceState` لا `pushState`: الفلترة ليست تنقّلًا، وزر الرجوع يجب أن يعيد المستخدم
  للصفحة السابقة لا للفلتر السابق.
- القيم المجهولة في الرابط تُتجاهل (الحارس القائم في `initFiltersFromUrl` يبقى).
- الصفوف تنزلق أفقيًا على الجوّال: `overflow-x: auto` + `scrollbar-width: none`.

| الملف | التعديل |
|---|---|

| `assets/css/styles.css` | قسم جديد **بعد** طبقة الثيم (بعد سطر ١٠٤٧) |

| `index.html` | لا شيء — يرث البطاقة عبر `renderFeatured()` |

### ٦.١ الترتيب في CSS حرج

القواعد القائمة في طبقة الثيم:

```css
.project-card, .punit-card { padding: 12px; }                    /* سطر ١٠٤٣ */
.project-card__media { border-radius: 14px; box-shadow: var(--inset); padding: 10px; }
```

نبني **فوقها** لا نستبدلها: الحشوة والإطار الغائر مطلوبان في التصميم الجديد. الجديد
يضيف `position: relative`، النسبة ٤:٥، وطبقات التراكب. القواعد القديمة الخاصّة بالجسم
الأبيض (`.project-card__body`, `.project-card__foot`, `.project-card__price`, `.sold`)
تُحذف من القسم ٣١٠–٤١٥ لأنها لن تُستخدم — عدا `.link-arrow` التي تُستعمل في صفحات أخرى.

## ٧. التحقق

`main.js` ملف IIFE للمتصفّح لا وحدة ES، فلا ينفع استيراده في `node --test`. ولأن التغيير
عرضٌ بصري بلا منطق أعمال جديد، التحقق بصري آلي عبر `/browse`:

- ٣ عروض: ١٤٤٠px (٣ أعمدة) · ٧٦٨px (عمودان) · ٣٩٠px (عمود)
- وضعان: فاتح وداكن — **مع التأكد أن التدرّج بقي داكنًا في الوضع الداكن** (المزلق في ٤.١)
- ٣ لغات: عربي، إنجليزي، صيني — مع فحص انقلاب اتجاه الشرائح
- حالات وظيفية: «جدة» ← رسالة «قريبًا» سليمة · مدينة + نوع بلا نتيجة ← الرسالة الجافّة ·
  الرجوع للخلف بعد الفلترة يغادر الصفحة لا يتراجع في الفلاتر
- الرئيسية: البطاقة المميّزة ورثت الشكل الجديد بلا كسر

## ٨. خارج النطاق

- حقل «موعد التسليم» (يحتاج عمودًا جديدًا + حقل لوحة تحكّم + تعبئة يدوية)
- شعار المطوّر على البطاقة (لا علاقة مطوِّر↔مشروع في المخطط)
- بحث نصّي أو فلتر سعر
- صفحة تفاصيل المشروع — لا تُمسّ
